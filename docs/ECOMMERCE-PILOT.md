# AIadmin 电商运营壳：内部试用与验收

2026-10-23（北京时间）。目标：为思域牵头的月底内部试用提供可运行入口与验收依据。当前为本机单操作者、人工文件导入、只读分析版本，没有店铺后台连接、模型调用或收费服务。

## 开始试用

1. Windows 安装 Python 3.12 或更新版，保留 Python Launcher 或加入 PATH。解压完整试用包到本地目录；支持中文及空格路径。不要只下载 HTML 文件。
2. 双击根目录 `启动电商运营壳.cmd`，保留命令窗口。脚本先检查 Python、SQLite 和分析模块，然后启动本地服务。浏览器若打开过早，看到命令窗口出现服务地址后刷新。
3. 浏览器访问 `http://127.0.0.1:8766`。先点击“载入演示数据（合成）”体验，所有演示记录明确标注，默认空库不注入记录。
4. 下载空白 CSV 模板。每批仅填同店、同物理仓库、同区间数据；填写来源、导出时间及业务口径，选择真实业务/演示/模拟测试后上传。
5. 查看数据质量、库存提示、价格采购异常、贡献利润。给异常分配负责人，记录核查依据；关闭异常必须填写备注。
6. 下载报告 ZIP，内含 Markdown 报告、CSV 结果、JSON 分析和异常修改历史。重新打开页面、重启服务后，可继续查看本机历史记录。
7. 停止：命令窗口按 Ctrl+C。默认数据目录 `%LOCALAPPDATA%\AIadmin\ecommerce-pilot`。停服后复制整个目录备份；恢复时停服，把备份复制到一个新目录，再通过 `-DataDir` 指向它。勿把业务数据库、CSV或报告提交到公开GitHub。

从源码启动（在仓库根目录）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-ecommerce.ps1
# 检查环境而不启动
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-ecommerce.ps1 -CheckOnly -NoBrowser
# 更换数据目录或端口
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-ecommerce.ps1 -DataDir 'D:\运营数据\试用一组' -Port 8876
```

`ExecutionPolicy Bypass` 仅用于本次脚本进程，不修改系统全局执行策略。运行不安装技能、不修改模型认证、不需要商家密钥。端口占用或目录无写权限时停止并提示。没有Python时不会自动安装软件。

Linux / macOS（Python 3.12+）：

```bash
python -m workbench.ecommerce serve --data-dir '/tmp/运营试用' --port 8766
```

既有内容工作台 `python -m workbench serve` 增加电商入口，内容与电商记录分表。本试用启动命令将电商页作为首页，并保持模型调用关闭。

轻量源码试用包只包含本轮12项运营测试和两项实际复用的计算/质量工具。包内可执行 `python -m unittest tests.test_ecommerce -v` 和 `python scripts/verify-ecommerce.py`；下文84项工作台与36项电商完整回归命令用于完整GitHub源码仓库。

## 文件与数据契约

CSV 支持 UTF-8 BOM、UTF-8 和 GB18030。XLSX 只读一张表，不接受公式、宏、外链或布尔/错误值；公式须在 Excel 中复制后“粘贴为值”。不支持旧 `.xls`。最多4MB、5000条数据行、40列，单元格最长500字符。使用模板中的中文列名，或对应英文键；未知/重复表头拒绝，不静默丢弃。SKU和记录ID在 Excel 中设为文本，避免前导零丢失。

必填列：

| 列 | 英文键 | 口径 |
|---|---|---|
| 记录ID | record_id | 本批唯一、非空 |
| SKU | sku | 本批唯一，同店同物理仓的商品标识 |
| 现存库存 | on_hand | 件，包含已占库存；不能填“已扣占用”的可售数 |
| 已占库存 | reserved | 件，已预留且尚未出库 |
| 安全库存 | safety | 件，运营输入的保留量 |
| 区间销量 | sales_units | 件，必须与统计区间一致，口径说明是否扣退货 |
| 采购交期天数 | lead_days | 非负整数天，人工确认的交付周期 |

可选列：

| 分析 | 中文列 / 英文键 | 缺失时行为 |
|---|---|---|
| 售价异常 | 当前售价/unit_price、售价底线/price_floor | 任一缺失则不检查，不推断平台实际券后价 |
| 采购价核对 | 采购单价/purchase_price、采购合同单价/contract_price | 任一缺失则不检查；比较输入金额是否相等 |
| 采购量提示 | 拟采购数量/purchase_qty | 缺失不提示，输入低于建议时提醒 |
| 贡献利润、广告ROAS | 净收入/net_revenue、另计到账补贴/merchant_subsidy、货品成本/goods_cost、平台费用/platform_fees、广告花费/ad_spend、履约成本/fulfillment_cost、售后净损失/after_sales_net_loss、其他变动成本/other_variable_cost | 8项必须齐全，空白不当作0；广告花费为0时ROAS不可计算 |

所有数值须有限、非负、不超过一万亿元或件、最多6位小数。库存、销量、交期和拟采购量须整数。退款/负收入数据须先按统一口径对账，首版不接受负数净收入。金额为 CNY，不自动换汇。

“净收入”不包含另计的到账补贴；`merchant_subsidy` 只填结算中另计、实际归商家的收入，不把商家自己承担的优惠当成额外收入，不能与净收入重复计入。各项成本须同一区间且无重复归集；不确定时留空并核对，不用0填充未知值。

来源元数据全部必填：店铺/物理仓、平台、来源说明、导出时间、统计起止时间、口径和数据类型。时间按本机时区输入，保存带时区的时间戳。统计结束为不含该时点；开始须早于结束、结束不晚于导出和当前时间。文件导出超过7天或处于未来时，质量门禁阻止经营建议。查看旧记录和导出前重新检查时效；原始导入时间及当时生成的异常待办保留，不据此自动创建新的店铺动作。

真实业务数据标签只代表人工声明，系统不证明文件来自后台。人工误标风险仍需负责人核实。首次试用没有收到真实经营文件，因此尚无真实业务验收结论。

## 计算口径

- 可用库存 = max(0, 现存库存 − 已占库存 − 安全库存)。复用 v6 `ecom_tools.calculate('inventory')`，按本批每个SKU单独计算。
- 日均销量 = 区间销量 ÷ 区间天数（由带时区起止时间计算）。覆盖天数 = 可用库存 ÷ 日均销量。销量0时显示“不可估计”。
- 覆盖天数 ≤ 采购交期时提示断货风险。补货复核量 = max(0, 向上取整(日均销量 × 交期) − 可用库存)。这是按历史均速的初步提示，未扣在途、未计季节性、促销、最小起订量或现金预算，不可直接下单。
- 已占+安全超过现存时提示口径异常。当前售价低于输入底线、采购价与输入合同价不等时提示核对，不擅自选择阈值或改价。
- 贡献利润 = 净收入 + 另计到账补贴 − 货品成本 − 平台费用 − 广告花费 − 履约成本 − 售后净损失 − 其他变动成本。直接复用 v6 利润计算；负值生成异常。未计固定费用或税项时不称净利润，不称现金流。
- 汇总仅覆盖本批成本齐全的行，页面同时显示利润覆盖行数。不同批次、店铺、共享物理仓库存不合计，避免重复计算。没有自动识别同仓跨店共享库存。
- 异常流程：待处理、处理中、已关闭。负责人和核查备注可修改，关闭必填备注，使用版本检查防覆盖并保留历史。人工关闭不等于已执行采购、修改店铺或验证经营改善。
