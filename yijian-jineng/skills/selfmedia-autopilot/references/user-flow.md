# 面向用户的流程

先查看进度，明确当前任务与阻塞点。没有真实台账时从一个产品、一个账号、一条内容开始，避免一次填写所有平台。

1. 策划输入：产品资料、目标人群、已核实卖点、希望的内容形式；缺必要资料时只询问当前环节需要的信息。
2. 学习输出：来源和热度证据、结构拆解、可迁移的逻辑；不用“爆款”承诺结果，不复制原文。
3. 电脑制作：交付可打开的正文、图片或视频，展示一个预览与保存位置。先使用当前助手原生生成；只有明确选择 API 才询问 API 配置。
4. 草稿准备：只配置当前账号所需的设备和页面；质检与真实校准通过后准备草稿。用户看到账号、平台、正文与素材预览、可见性。
5. 提交核验：针对当前精确草稿确认并执行一次提交。结果不明先查作品，保留锁，不以超时为由重发。
6. 数据复盘：导入真实数据，给出下一批可验证的改进假设。

向用户解释“缺资料”“需校准”“设备占用”“等待草稿确认”“结果待核验”，不要只显示堆栈。示例文件不算配置完成；代码测试通过不算平台发布通过。普通豆包、千问客户端只能获得资料和指令，设备控制需要有本机执行能力的宿主。

暂未实现的体验能力应清楚说明：交互式账号配置表单、自动页面变化检测、平台数据自动回收、主机级定时调度、全部平台真实验收。当前日历是规划，当前进度页是离线快照。不要把这些描述为已运行功能。
