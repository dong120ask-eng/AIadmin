## 一、工作流架构总览

### 核心目标
一键跑通从产品录入→卖点锁定→词库生成→内容生产→成果打包的全流程自动化，上游输出严格作为下游输入，全链路卖点100%统一。

### 执行环境
字节跳动扣子Coze工作流，所有插件、节点100%匹配扣子官方原生生态。

### 节点流程图
```
节点0（全局变量初始化）
    ↓
节点1（多模态产品录入）
    ├─ 分支1-1：图片批量录入
    ├─ 分支1-2：电商链接录入
    ├─ 分支1-3：手动信息录入
    └─ 节点1-4：统一数据格式化
    ↓
节点2（核心卖点挖掘）
    ↓
节点3（GEO+SEO词库生成）
    ↓
节点4（GEO问答内容生成）
    ↓
节点5（多平台内容矩阵生成）
    ├─ 子节点5-1：电商平台物料
    ├─ 子节点5-2：短视频带货内容
    ├─ 子节点5-3：图文种草内容
    └─ 子节点5-4：SEO长文内容
    ↓

    ↓

```

## 二、节点详细配置

### 节点0：全局变量初始化节点

**节点类型**：Python代码节点

**核心功能**：初始化全流程唯一全局变量容器，锁死全流程核心数据，所有下游节点强制读取调用，禁止私自变更。

**初始化固定变量名**：
```python
# 初始化全局变量容器
global_vars = {
    "Global_Product_Profile": None,  # 产品标准化档案（下游录入节点写入）
    "Global_Core_Sell": None,        # 全流程唯一核心卖点（下游卖点节点写入，全流程不可变更）
    "Global_Assist_Sell": None,      # 3个辅助卖点数组（下游卖点节点写入）
    "Global_Keyword_Library": None   # GEO+SEO双引擎词库（下游词库节点写入）
}
```

**输出**：全流程可跨节点调用的全局变量容器

**使用方式**：所有下游节点通过引用 `{{global_vars.Global_Core_Sell}}` 等方式调用全局变量

### 节点1：多模态产品录入层

#### 分支1-1：图片批量录入通道

**节点类型**：插件节点 → 扣子官方「通用OCR识别」插件 + 「图片理解」插件

**输入**：用户上传的商品图片（包装/实拍/资质图，支持批量上传）

**执行逻辑**：
1. 先用OCR提取图片全量文本信息
2. 再用图片理解补充产品视觉信息（颜色、包装形态、规格）

**输出**：`Image_Parse_Result` 图片解析结构化文本

#### 分支1-2：电商链接一键录入通道

**节点类型**：插件节点 → 扣子官方「网页抓取」插件

**输入**：用户输入的京东/天猫/拼多多/抖店/美团商品公开详情页链接

**执行逻辑**：仅抓取页面公开的商品标题、规格参数、详情页文案、价格、类目、核心卖点信息，禁止抓取非公开数据。

**输出**：`Link_Parse_Result` 链接解析结构化文本

#### 分支1-3：手动信息录入通道

**节点类型**：表单节点

**输入**：用户手动填写的产品通用名、品牌名、核心功能、规格、产地、适用人群基础信息

**输出**：`Manual_Input_Result` 手动录入结构化文本

#### 节点1-4：统一数据格式化节点

**节点类型**：Python代码节点

**输入**：分支1-1/1-2/1-3的任意解析结果，多分支输入自动合并去重

**执行逻辑**：将多源非结构化文本，映射为固定Schema的标准化产品档案，缺失字段标注为「待补充」，禁止编造任何无依据数据。

**固定Schema**（必须严格执行，不可修改字段）：
```json
{
  "base_info": {
    "product_name": "产品通用名",
    "brand_name": "品牌名",
    "category": "所属类目",
    "spec": "规格含量",
    "price": "价格区间",
    "origin": "原料/生产产地"
  },
  "product_attr": {
    "core_ingredient": "核心成分",
    "craft": "生产工艺",
    "core_function": "核心功能",
    "pack_info": "包装信息",
    "target_user": "适用人群"
  },
  "brand_qualification": {
    "enterprise_name": "生产企业名称",
    "patent_info": "专利资质",
    "authority_endorsement": "权威背书"
  }
}
```

**输出**：标准化产品档案 → 强制写入节点0的 `Global_Product_Profile` 全局变量

### 节点2：核心卖点挖掘层

**节点类型**：大语言模型LLM节点（默认豆包4.0 Ultra）

**输入**：节点1输出的 `Global_Product_Profile` 标准化产品档案

**系统提示词**（强制锁死，不可修改）：
```
【角色】你是电商爆款差异化卖点挖掘专家，仅基于输入的产品档案输出结果，禁止编造任何无依据的内容
【核心规则】
1. 输出1个**唯一、贯穿全流程、不可变更**的核心卖点，必须是产品差异化优势，直击用户核心痛点
2. 输出3个辅助卖点，每个卖点对应一个产品可验证的优势，与核心卖点形成互补，不重复
3. 输出格式必须为严格JSON格式，仅输出JSON，禁止其他任何多余内容、解释、寒暄

**输出**：核心卖点+辅助卖点结构化数据 → 强制写入节点0的 `Global_Core_Sell`、`Global_Assist_Sell` 全局变量

### 节点3：GEO+SEO双引擎词库生成层

**节点类型**：Python代码节点 + 扣子官方「关键词提取」插件

**输入**：节点0的 `Global_Product_Profile`、`Global_Core_Sell`、`Global_Assist_Sell` 全量全局变量

**执行逻辑**：
1. 先用关键词提取插件，从产品档案和卖点中提取核心词根（产品通用名、品牌名、核心功能、用户痛点词）
2. 用Python代码批量拓展GEO/SEO全维度关键词，无外部API时自动用内置行业高频词库+模拟数据跑通流程，不中断执行
3. GEO优化评分公式：`(用户提问频次*0.5 + 大模型引用优先级*0.5) / 内容竞争度`，归一化至0-100分
4. SEO优化评分公式：`(月搜索量*0.4 + 转化率*0.4) / 关键词竞争度*0.2`，归一化至0-100分

**输出固定字段的关键词库表格**：
- 关键词
- 关键词类型
- GEO优化评分
- SEO优化评分
- 适用平台
- 适用场景

**输出结果**：强制写入节点0的 `Global_Keyword_Library` 全局变量

**异常配置**：无API数据时自动降级为内置行业高频词库，保证流程不中断

## 三、全局约束规则

### 全LLM节点全局强制约束

每个LLM节点必须100%写入系统提示词最开头，不可修改：

1. **【卖点一致性铁律】**：本节点所有输出的核心卖点，必须与全局变量 `Global_Core_Sell` 100%完全统一，禁止任何偏离、变更、新增核心卖点

2. **【落地性原则】**：所有输出必须是直接可复制、可上架、可发布的成品文案，禁止空泛理论、禁止方法论、禁止无关解释、禁止寒暄

3. **【GEO权重优化规则】**：所有提问句、标题必须模拟真人对AI说话的口语习惯，必须包含产品通用名+核心卖点核心词根，禁止纯关键词堆砌

4. **【格式约束】**：必须严格按照要求的格式输出，禁止多余的备注、解释内容，仅输出任务要求的成品内容

5. **【无编造规则】**：所有内容必须基于输入的产品档案生成，禁止编造无依据的功效、资质、数据

## 四、运行配置

### 触发方式
用户上传图片/输入链接/填写表单后，点击「启动执行」一键触发全流程。

### 异常处理
- 每个节点设置3次自动重试
- 重试失败后触发降级分支，不中断全流程运行
- 最终输出失败节点的人工处理提示

### 人工干预入口
- 每个节点输出后支持用户手动修改
- 修改后自动更新对应全局变量
- 可选择继续执行后续节点或重新执行当前节点

## 五、常见问题

### Q1：节点配置失败怎么办？
**A**：
1. 检查所有节点是否正确连接
2. 检查全局变量引用是否正确（`{{global_vars.xxx}}`）
3. 检查系统提示词是否完整复制

### Q2：卖点不一致怎么办？
**A**：
1. 检查所有LLM节点是否包含【卖点一致性铁律】
2. 检查节点2的输出是否正确写入全局变量
3. 检查下游节点是否正确引用 `Global_Core_Sell`

### Q3：自媒体平台推荐不准确怎么办？
**A**：
1. 检查产品档案中的 `category` 和 `target_user` 字段
2. 根据产品特点手动调整平台推荐
3. 参考SKILL.md中的自媒体平台智能推荐规则

### Q4：内容生成失败怎么办？
**A**：
1. 检查输入的产品档案是否完整
2. 检查全局变量是否正确初始化
3. 检查LLM节点是否配置正确的系统提示词

### Q5：合规筛查失败怎么办？
**A**：
1. 检查合规审核插件是否正确配置
2. 检查内容是否包含严重违规词
3. 手动修改违规内容后重新运行

## 第一阶段：工作流节点架构配置（按顺序执行，锁死上下游数据链路，Auto-Agent自动识别连线）
### 节点0：全局变量初始化节点【前置必选，根上解决卖点不统一问题】
- 节点类型：Python代码节点
- 核心功能：初始化全流程唯一全局变量容器，锁死全流程核心数据，所有下游节点强制读取调用，禁止私自变更
- 初始化固定变量名：
  1.  Global_Product_Profile：产品标准化档案（下游录入节点写入）
  2.  Global_Core_Sell：全流程唯一核心卖点（下游卖点节点写入，全流程不可变更）
  3.  Global_Assist_Sell：3个辅助卖点数组（下游卖点节点写入）
  4.  Global_Keyword_Library：GEO+SEO双引擎词库（下游词库节点写入）
- 输出：全流程可跨节点调用的全局变量容器

### 节点1：多模态产品录入层【3个并行分支，最终统一数据格式，用户任选其一即可触发】
#### 分支1-1：图片批量录入通道
- 节点类型：插件节点 → 扣子官方「通用OCR识别」插件 + 「图片理解」插件
- 输入：用户上传的商品图片（包装/实拍/资质图，支持批量上传）
- 执行逻辑：先用OCR提取图片全量文本信息，再用图片理解补充产品视觉信息（颜色、包装形态、规格）
- 输出：Image_Parse_Result 图片解析结构化文本

#### 分支1-2：电商链接一键录入通道
- 节点类型：插件节点 → 扣子官方「网页抓取」插件
- 输入：用户输入的京东/天猫/拼多多/抖店/美团商品公开详情页链接
- 执行逻辑：仅抓取页面公开的商品标题、规格参数、详情页文案、价格、类目、核心卖点信息，禁止抓取非公开数据
- 输出：Link_Parse_Result 链接解析结构化文本

#### 分支1-3：手动信息录入通道
- 节点类型：表单节点
- 输入：用户手动填写的产品通用名、品牌名、核心功能、规格、产地、适用人群基础信息
- 输出：Manual_Input_Result 手动录入结构化文本

#### 节点1-4：统一数据格式化节点
- 节点类型：Python代码节点
- 输入：分支1-1/1-2/1-3的任意解析结果，多分支输入自动合并去重
- 执行逻辑：将多源非结构化文本，映射为固定Schema的标准化产品档案，缺失字段标注为「待补充」，禁止编造任何无依据数据
- 固定Schema（必须严格执行，不可修改字段）：
```json
{
  "base_info": {"product_name": "产品通用名", "brand_name": "品牌名", "category": "所属类目", "spec": "规格含量", "price": "价格区间", "origin": "原料/生产产地"},
  "product_attr": {"core_ingredient": "核心成分", "craft": "生产工艺", "core_function": "核心功能", "pack_info": "包装信息", "target_user": "适用人群"},
  "brand_qualification": {"enterprise_name": "生产企业名称", "patent_info": "专利资质", "authority_endorsement": "权威背书"}
}
```
- 输出：标准化产品档案 → 强制写入节点0的 Global_Product_Profile 全局变量

### 节点2：核心卖点挖掘层
- 节点类型：大语言模型LLM节点（默认豆包4.0 Ultra）
- 输入：节点1输出的 Global_Product_Profile 标准化产品档案

```

【核心规则】
1.  输出1个**唯一、贯穿全流程、不可变更**的核心卖点，必须是产品差异化优势，直击用户核心痛点
2.  输出3个辅助卖点，每个卖点对应一个产品可验证的优势，与核心卖点形成互补，不重复

### 节点3：GEO+SEO双引擎词库生成层
- 节点类型：Python代码节点 + 扣子官方「关键词提取」插件
- 输入：节点0的 Global_Product_Profile、Global_Core_Sell、Global_Assist_Sell 全量全局变量
- 执行逻辑：
  1.  先用关键词提取插件，从产品档案和卖点中提取核心词根（产品通用名、品牌名、核心功能、用户痛点词）
  2.  用Python代码批量拓展GEO/SEO全维度关键词，无外部API时自动用内置行业高频词库+模拟数据跑通流程，不中断执行
  3.  GEO优化评分公式：(用户提问频次*0.5 + 大模型引用优先级*0.5) / 内容竞争度，归一化至0-100分
  4.  SEO优化评分公式：(月搜索量*0.4 + 转化率*0.4) / 关键词竞争度*0.2，归一化至0-100分
- 输出固定字段的关键词库表格，必填字段：关键词、关键词类型、GEO优化评分、SEO优化评分、适用平台、适用场景
- 输出结果：强制写入节点0的 Global_Keyword_Library 全局变量
- 异常配置：无API数据时自动降级为内置行业高频词库，保证流程不中断
