# GEO提示词架构

构建与客户真实业务匹配的GEO提示词系统，而非通用关键词列表。

## 概述

使用本技能为GEO项目生成和审计AI可见性监控提示词。它将客户简报转化为跨非品牌发现、竞品对比和品牌防御的 `主题 -> 提示词` 架构，然后帮助将监控结果转化为具体的优化行动。

## 最适合的场景

- GEO软件团队为新客户进行入职
- 以规模化方式构建提示词集的GEO代理
- 需要按主题、产品线和漏斗阶段获得更好提示词覆盖的操作员
- 想要重新平衡提示词库以减少品牌偏见的团队
- 想要将监控提示词与后期内容和资产优化联系起来的团队

## 从这里开始

```
使用 $geo-prompt-architecture 为此客户生成GEO监控提示词。
```

```
使用 $geo-prompt-architecture 审查此提示词集并重新平衡品牌与非品牌提示词。
```

```
使用 $geo-prompt-architecture 将这些监控结果转化为提示词和内容建议。
```

## 核心模型

始终将GEO提示词框架为 `主题优先` 系统：

1. `主题地图`
   决定哪些问题空间、类别、用例、信任问题、竞品群组、渠道和季节性主题值得监控。

2. `非品牌发现`
   用户尚不知道品牌。这些提示词衡量品牌是否能进入新的答案空间。

3. `竞品对比`
   用户正在比较品牌、替代品或解决方案路线。这些提示词衡量竞争可见性。

4. `品牌防御`
   用户已经知道品牌，正在验证适合度、质量、定价、尺寸、运输、退货或价值。这些提示词衡量叙事控制和决策阶段表现。

主题来源可以是：
- 用户提供的优先主题
- 转化为主题种子的产品线
- 从网站、商业模式、用例、竞品、渠道和弱AI表面推断的主题

默认包大小：
- `5` 个主题
- `50` 个提示词总计
- 每个主题 `10` 个提示词

默认包组合：
- `30-32` 个非品牌发现提示词
- `12-15` 个竞品对比提示词
- `5-8` 个明确品牌提示词

每个主题推荐的起始形状：
- `6` 个非品牌发现提示词
- `3` 个竞品对比提示词
- `1` 个品牌防御提示词

默认目标组合：
- `60-70%` 非品牌发现
- `20-25%` 竞品对比
- `10-20%` 品牌防御

除非用户明确要求，否则不要让品牌提示词占主导。

## 工作流程

### 1. 重构客户模型

在生成提示词之前，识别：
- 商业模式
- 市场和语言
- 目标客户
- 用户提供的主题（如果有）
- 核心产品线（如果有）
- 转化路径
- 主要竞品
- 弱AI表面（如果有）

有用的商业模式标签：
- SaaS / 软件
- 电商 / DTC
- 服务 / 咨询
- 市场 / 聚合
- 制造商 / 供应商
- 内容 / 媒体

如果输入不完整，仔细推断并标记推断内容。

### 2. 构建主题地图

不要直接跳到提示词。

首先，构建一个解释监控系统的覆盖范围的主题地图。

优先级顺序：
1. 规范化用户提供的优先主题
2. 将产品线转为主题种子
3. 从以下方面推断缺失的主题：
   - 用例
   - 受众细分
   - 竞品重叠
   - 信任和评估问题
   - 渠道和市场
   - 季节性和趋势模式

有用的主题类型：
- 产品/类别
- 用例
- 受众/细分
- 竞品/替代
- 信任/评估
- 渠道/市场
- 季节/趋势

每个输出应清楚说明主题是：
- `provided`（提供）
- `derived-from-product-line`（从产品线派生）
- `inferred`（推断）

如果系统识别出超过5个有效主题，按以下因素选择前5个：
- 商业价值
- 监控价值
- GEO杠杆
- 竞品压力
- 渠道契合度

### 3. 映射漏斗

提示词输出应使用营销漏斗标签：
- `TOFU`（漏斗顶部）
- `MOFU`（漏斗中部）
- `BOFU`（漏斗底部）

默认映射：
- `问题认知` -> `TOFU`
- `解决方案教育` -> `TOFU`
- `类别评估` -> `MOFU`
- `品牌对比` -> `MOFU`
- `购买决策` -> `BOFU`
- `使用/实施/扩展` -> `BOFU`

商业意图覆盖：
- 如果提示词明显是采购主导、产品规格特定、供应商/卖家选择导向或近期购买导向，即使看起来像类别评估或对比，也优先 `BOFU`

### 4. 按主题生成提示词集

在每个主题内生成提示词。保持层次分离：
- 非品牌发现提示词
- 竞品对比提示词
- 品牌防御提示词

如果存在产品线，使用它们作为分组维度之一，但不要将其视为强制性的。有些客户需要按以下分组：
- 主题优先
- 产品线优先
- 漏斗阶段优先

## 输出结构

每个提示词应包含：
- 提示词文本
- 目标漏斗阶段（TOFU/MOFU/BOFU）
- 提示词类型（非品牌/竞品/品牌）
- 来源主题
- 预期的AI行为或回答类型

### 标准输出格式

```json
{
  "client": "[品牌名称]",
  "generated_date": "[日期]",
  "topics": [
    {
      "topic": "[主题名称]",
      "topic_type": "provided|derived|inferred",
      "prompts": [
        {
          "text": "[提示词文本]",
          "type": "non-brand|comparison|brand",
          "funnel_stage": "TOFU|MOFU|BOFU",
          "expected_ai_behavior": "[描述AI应该如何回答]"
        }
      ]
    }
  ],
  "summary": {
    "total_prompts": 50,
    "non_brand_count": 32,
    "comparison_count": 12,
    "brand_count": 6,
    "topical_coverage": "[覆盖说明]"
  }
}
```

## 评分框架

评估提示词集的质量：

### 覆盖度评分
- 每个主题是否有足够数量的提示词？
- 是否覆盖所有漏斗阶段？
- 非品牌 vs 品牌的平衡是否适当？

### 多样性评分
- 提示词是否涵盖不同类型的用户问题？
- 是否避免了太多相似的提示词？

### 商业相关性评分
- 提示词是否与客户的真实业务相关？
- 是否捕捉了客户想要排名的关键主题？

### 可操作性评分
- 监控结果能否转化为具体的内容行动？
- 提示词是否足够具体以产生可用的见解？

## 最佳实践

1. **从主题开始，不是关键词**
   强GEO监控始于正确的主题宇宙，而非正确的提示词措辞。

2. **平衡品牌 vs 非品牌**
   品牌可能在品牌提示词上看起来可见，但在推动增长的非品牌答案空间中仍然失败。

3. **按漏斗阶段思考**
   TOFU提示词衡量发现能力。BOFU提示词衡量转化能力。两者都需要。

4. **定期更新**
   AI搜索行为变化迅速。定期重新评估提示词集的覆盖度。

5. **连接监控到优化**
   监控结果应直接转化为内容创作和优化行动。
