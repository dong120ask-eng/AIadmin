# GEO Reporter 审计编排技能

## 目的

本技能对任何网站执行全面的生成式引擎优化（ GEO ）审计。GEO是优化网页内容以便AI系统（ ChatGPT、Claude、Perplexity、Gemini等）能够发现、理解、引用和推荐内容的实践。本审计衡量网站在所有GEO维度上的表现，并生成可操作的改进方案。

## 核心洞察

传统SEO优化搜索引擎排名。GEO优化AI引用和推荐。在GEO指标上得分高的网站，AI生成响应中的可见度提高30-115%（ Georgia Tech / Princeton / IIT Delhi 2024研究）。两个学科有重叠但有不同要求。

## 审计工作流程

### 第一阶段：发现与侦察

**步骤1：获取首页并检测业务类型**

1. 使用WebFetch检索首页URL
2. 提取以下信号：
   - 页面标题、元描述、H1标题
   - 导航菜单项（揭示网站结构）
   - 页脚内容（揭示商业信息、位置、法律页面）
   - 首页的Schema.org标记（Organization、LocalBusiness等）
   - 定价页面链接（ SaaS指标）
   - 产品列表模式（电商指标）
   - 博客/资源部分（发布者指标）
   - 服务页面（代理指标）
   - 地址/电话/ Google Maps嵌入（本地业务指标）

3. 使用这些模式分类业务类型：

| 业务类型 | 检测信号 |
|---|---|
| **SaaS** | 定价页面、"注册"/"免费试用" CTA、app.domain.com子域、功能对比表、集成页面 |
| **本地业务** | 首页上的实际地址、Google Maps嵌入、"附近"内容、LocalBusiness schema、服务区域页面 |
| **电商** | 产品列表、购物车、产品schema、类别页面、价格展示、"加入购物车"按钮 |
| **发布商** | 博客主导导航、文章schema、作者页面、按日期归档、RSS提要、高内容量 |
| **代理/服务** | 案例研究、作品集、"我们的工作"部分、团队页面、客户logo、服务描述 |
| **混合型** | 以上信号组合——按主导模式分类 |

**步骤2：抓取站点地图和内部链接**

1. 尝试获取 `/sitemap.xml` 和 `/sitemap_index.xml`
2. 如果站点地图存在，提取最多50个唯一页面URL，按以下优先级排序：
   - 首页（始终包含）
   - 顶级导航页面
   - 高价值页面（定价、关于、联系、关键服务/产品页面）
   - 博客文章（抽样5-10个最新）
   - 类别/落地页
3. 如果没有站点地图，从首页抓取内部链接：
   - 提取所有指向同一域名的 `<a href>` 链接
   - 深入跟踪最多2层
   - 优先从主导航链接的页面
4. 遵守 `robots.txt` 指令——不获取禁止的路径
5. 强制最大50个页面和每页30秒超时

**步骤3：收集页面级数据**

对于抓取集中的每个页面，记录：
- URL、标题、元描述、规范URL
- H1-H6标题结构
- 主要内容的词数
- 存在的Schema.org类型
- 内部/外部链接数
- 有/无alt文本的图像
- Open Graph和Twitter Card元标签
- 响应状态码
- 是否有结构化数据

---

### 第二阶段：并行子代理委托

委托给5个专业子代理进行分析。每个子代理在收集的页面数据上运行，并生成类别评分（0-100）和发现。

**子代理1：AI可见性分析（geo-ai-visibility）**
- 分析内容块的AI可引用性（引用性评分）
- 检查通过robots.txt和llms.txt的AI爬虫访问
- 扫描YouTube、Reddit、Wikipedia、LinkedIn上的品牌存在
- 评分AI模型用于实体识别的品牌权威信号

**子代理2：平台优化（geo-platform-analysis）**
- 评估Google AI Overviews、ChatGPT、Perplexity、Gemini、Bing Copilot的准备度
- 检查平台特定的排名因素和优化机会

**子代理3：技术GEO基础设施（geo-technical）**
- 分析AI爬虫访问的robots.txt
- 验证AI系统的元标签、头部和技术可访问性
- 检查页面速度、服务器端渲染和Core Web Vitals
- 评估安全头部和移动优化

**子代理4：内容E-E-A-T质量（geo-content）**
- 评估体验、专业性、权威性、可信度信号
- 检查作者简历、资质、来源引用
- 评估内容新鲜度、深度和原创性
- 验证"关于"页面质量和团队资质

**子代理5：Schema与结构化数据（geo-schema）**
- 验证所有schema.org标记
- 检查GEO关键schema类型（FAQ、HowTo、Organization、Product、Article）
- 评估schema完整性和准确性
- 识别缺失的schema机会

---

### 第三阶段：评分汇总与报告生成

#### 综合GEO评分计算

总体GEO评分（0-100）是六个类别评分的加权平均值：

| 类别 | 权重 | 衡量内容 |
|---|---|---|
| **AI引用性** | 25% | 内容对AI系统的可引用/可提取程度 |
| **品牌权威** | 20% | 第三方提及、实体识别信号 |
| **内容E-E-A-T** | 20% | 体验、专业性、权威性、可信度 |
| **技术GEO** | 15% | AI爬虫访问、llms.txt、渲染、速度 |
| **Schema与结构化数据** | 10% | Schema.org标记质量和完整性 |
| **平台优化** | 10% | AI模型训练和引用的平台存在 |

**公式：**
```
GEO_Score = (引用性 * 0.25) + (品牌 * 0.20) + (E-E-A-T * 0.20) + (技术 * 0.15) + (Schema * 0.10) + (平台 * 0.10)
```

#### 评分解读

| 评分范围 | 等级 | 说明 |
|---|---|---|
| 90-100 | 优秀 | 顶级GEO优化；网站极有可能被AI引用 |
| 75-89 | 良好 | 强大的GEO基础，有改进空间 |
| 60-74 | 一般 | 中等GEO存在；存在显著优化机会 |
| 40-59 | 较差 | 弱GEO信号；AI系统可能难以引用或推荐 |
| 0-39 | 危急 | 极少的GEO优化；在AI系统中基本不可见 |

## 问题严重程度分类

### 危急（立即修复）
- robots.txt中阻止所有AI爬虫
- 无可索引内容（仅JavaScript渲染，无SSR）
- 域名级别noindex指令
- 关键页面返回5xx错误
- 完全缺少任何结构化数据
- 品牌不被任何AI系统识别为实体

### 高优先级（1周内修复）
- 关键AI爬虫（GPTBot、ClaudeBot、PerplexityBot）被阻止
- 无llms.txt文件
- 关键页面上没有问答内容块
- 缺少Organization或LocalBusiness schema
- 内容页面无作者署名
- 所有内容在登录/付费墙后且无预览

### 中等优先级（1月内修复）
- 部分AI爬虫阻止（部分允许，部分阻止）
- llms.txt存在但不完整或格式错误
- 内容块平均引用性评分低于50
- 有FAQ内容的页面缺少FAQ schema
- 作者简历单薄，无资质
- 无Wikipedia或Reddit品牌存在

### 低优先级（尽可能优化）
- 次要schema验证错误
- 部分图像缺少alt文本
- 非关键页面的内容新鲜度问题
- 缺少Open Graph标签
- 部分页面标题层次结构不优
- LinkedIn公司页面存在但不完整
