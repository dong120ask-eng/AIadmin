# 四助手与Codex的部署调用
源套件 skills/ 是唯一版本，脚本/知识资源随技能一起复制。tools/deploy.py 默认只打印计划，apply部署，差异文件backup先保留。
- DeepSeek Harness：工作目录/.dsh/skills。
- WorkBuddy/CodeBuddy：工作目录/.codebuddy/skills。
- Codex/通用：工作目录/.agents/skills。
- 豆包、千问普通聊天端：上传产品/技能方法文件并按当前工具能力调用；没有本机或手机权限时只生成内容和交接指令，不能假报已部署。
- 豆包/千问/DeepSeek API模式：复制providers.example.json为用户配置，填写真实模型名与环境变量引用；选定端点后generate.py才发请求。此路径与聊天客户端不同。

## 复制给具备本地工具的助手
~~~text
工作目录 D:\一键自动化技能。读取 selfmedia-autopilot，使用本地自媒体技能套件和项目Python环境。
先读取交付说明、技能清单和未验收项；这是开发版，本次先开发后测试，不沿用旧文档“全部实测完成”的说法。
用 product-market-marketing 按我给的产品做市场营销策划；再用 viral-content-learning 和 content-framework-remix 学习授权样本的框架逻辑，独立创作。
按分类、产品、账号人设和平台制作 campaign 计划，每个账号独立job。先电脑生成、保存并QA，再交手机、逍遥实例或网页账号准备草稿。
使用真实账号登记、设备锁、素材指纹、实际预览和当前任务审批。最终发布由对应publish-*与控制器执行，提交前一次attempt，实际核验后complete，结果不明不重发。
下一阶段由我们逐平台测试账号、界面定位、草稿、提交和结果，不把开发静态校验当成运营验收。
~~~

## 豆包和千问无本机工具时
~~~text
读取我上传的营销与自媒体技能材料，根据产品事实先做策划，再学习样本框架，产出各账号独立正文、卡片规格、视频脚本和资料来源。
输出给本地执行助手的任务JSON与制作步骤，不声称访问了D盘、安装了App或完成发布。缺少事实和账号资料先标明，不能虚构。
~~~
