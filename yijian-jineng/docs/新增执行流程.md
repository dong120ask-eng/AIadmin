# 新增执行流程

Python与完整包路径从deployment-latest.json读取；当前开发目录也可直接使用实际便携Python。样例只是格式，不含真实账号或事实审批。

1. 素材导入：sources.py --root ROOT --file 原文HTML/MD/RSS --metadata 来源JSON；来源需真实链接、公开/授权范围和带时区采集时间。
2. 营销与框架：产品事实、定位、框架记录完成后，remix.py产出messages。原生助手使用这些消息创作；API模式需选定模型和预算。
3. 生成落盘：matrix.py产出计划。原生助手输出title/body/cards/segments等JSON，再accept.py --root ROOT --plan PLAN --job ID --content JSON；API模式generate.py --apply走同一接收器。
4. 制作与排版：media.py、formatting.py、adapt.py生成电脑文件。QA前检查实图/视频，不能以文本提示词当成成品。
5. 入队与审核：queue.py enroll --apply建立任务，quality.py --review REAL_REVIEW --output QA --apply仅在通过后转reviewed。审核者、事实与权利证据、平台规则、任务指纹必须真实。视频审核记录的video_quality_report含path/sha256/media_sha256，并指向全部通过的复核报告。
6. 校准：engine.py observe --root ROOT --task TASK --profile RAW --apply生成截图和结构证据；calibrate.py --observation ACTUAL --reviewer REVIEWER生成绑定配置。未校准配置不能填写或提交。
7. 草稿：ops.py claim，再engine.py prepare --apply。批量则tools/batch_prepare.py --spec BATCH先预检，apply后依次QA/claim/prepare/release；每项task_id/profile/review的路径均在ROOT内。
8. 发布：实际预览每个草稿，用户确认后ops.py approve/claim/begin，engine.py submit --apply仅提交一次。提交失败或后续截图失败保留uncertain。recovery.py先报告状态，实际核验作品后用verified-result恢复；不自动重发。
9. 复盘与下一批：analytics.py导入真实CSV，experiment.py比较正确二项指标，calendar.py规划带时区任务。export.py交接已审核成果，不搬登录态或审批。bridge.py按宿主部署或导出普通聊天知识包。

不从一个账号的校准推断另一个账号、分身或模拟器实例可用。App/网页无法实时确认身份时停止；USB序列号、多开实例、Android系统用户和当前作品账号逐项绑定。
