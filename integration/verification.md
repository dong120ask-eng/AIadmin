# 源码兼容性与验收报告

检查日期：2026-10-17。版本固定见 README。源码通过已连接 GitHub 接口读取，终端直接 git clone 失败，未绕过访问限制。GitHub 返回 AIadmin 为 private、专家仓库为 public；本次不修改可见性。

## 结论

可以复用，但不是把专家目录导入后自动获得数百个执行智能体。最小成本路线是：保留 AIadmin 的执行进程管理与 SQLite，新增开发任务适配器；角色指令和工作流来自专家仓库。当前提交是隔离实验入口，尚未接到工作台网页提交按钮。

| 核对项 | 实际源码 | 本次适配 / 边界 |
|---|---|---|
| 技能安装 | `scripts/install.py` 默认 CODEX_HOME/skills，角色到 agents，保留同名条目，替换有备份 | 隔离目录实测；不改 config.toml。桥接直接读源码路径，无全局安装依赖 |
| 角色配置 | 11 个 TOML 主要为 name/description/developer_instructions | 本次调用 product_analyst、backend_engineer、qa_engineer 的指令；不把 TOML 当原生角色注册成功证据 |

| 任务输入输出 | runner.run_job 限定 content_type/text_draft/payload | 新开发协议要求 role/status/summary/artifacts/limitations；不伪装文章，不改变原内容接口 |

## 能力数量的正确解释

实际解析 `catalog.json`：448 条，其中 15 条 full-role、433 条 catalog-only。15 条表示有许可明确的角色方法文本，仍不是15个已部署服务或模型。11 个角色配置可以被适配器作为独立模型会话的任务指令使用，需真实执行器支持。16 个技能是路由/工作法入口；3 类工作流是软件产品、研究判断、内容营销。

本轮真正调用的独立代理：产品分析师、开发者、独立 QA（当前 Work 的执行能力）。它们实际读取源码、实现适配器、执行独立测试并回报缺陷。不是从专家目录启动448个代理，也不证明 AIadmin CLI 运行时已贯通。

## 验证记录

1. AIadmin PR #3 固定版本现有72项测试全部通过。包括设备/媒体测试中的受控模拟，不代表手机或平台真实执行。
2. 专家原安装器14项测试通过；隔离安装检查16个技能入口、11个角色，路径替换和 TOML 解析通过。本轮取得的是针对性源码子集，未重跑整个专家库24项测试，不宣称完整引用库已安装验收。
3. 产品分析提出独立开发协议及验收条件；开发完成适配器；QA独立设计回归并发现问题。负责人复核并要求修复：产品需求必须完整交给QA、交付时重新核对开发文件哈希、禁止快照新增文件、避免内层无界输出缓冲。
4. 独立 QA 进一步发现“空QA测试文件借开发测试通过”的缺陷，列为阻断项，修复及最终测试数量见 `test-results.json`。
5. 默认CLI入口实测返回prepared，不执行模型。显式执行在本环境因Codex CLI缺失返回blocked，三个阶段均未启动，宿主测试为null；不会生成假完成。
6. 协议成功用例由确定性测试执行器提供三个角色产物，宿主真的执行示例Python测试。该记录标记 `injected_unverified`，不能当模型理解需求、真实CLI加载技能或生产质量的证据。

## 未完成的真实验收

需要有已认证 Codex CLI 的隔离本机环境，用 README 命令对一个小任务实测，核对：CLI版本/参数兼容、技能路径可读、三个独立会话事件、产物、QA独立测试数量和宿主结果。当前环境没有可用CLI，未自行更改认证或安装第三方执行器。

Windows实机与操作系统沙箱、模型费用、角色自动注册、任意已有仓库修改、多任务并发调度、网页提交入口、业务系统员工权限均未验收。

## 扩大并发前的条件

先保持每任务分析→开发→QA的依赖顺序。并发应优先用于相互独立任务，不把阶段依赖强行并行。

| 阶段 | 必要条件 |
|---|---|
| 本机小规模 | 实测CLI额度/超时/取消；独立worktree或源码快照；输入输出版本绑定；不共写文件；任务资源上限 |
| 多worker | 租约+心跳+fencing token，旧进程终止确认，恢复演练；当前单次CAS不足以支持安全自动重试 |
| 多租户 | 真实身份认证和权限检查、独立受限执行容器/账号、凭证隔离、网络出口策略；tenant字段本身不构成鉴权 |
| 跨主机 | 共享任务数据库/消息队列、对象存储、幂等与重复消息处理、日志审计、数据库迁移和备份 |
| 扩到几十个以上 | 模型并发/速率/预算控制、CPU内存磁盘配额、队列背压、公平调度、端到端负载测试与失败恢复 |

现阶段不需要重建智能体框架。先补真实CLI闭环，再把此入口接入工作台；之后再泛化现有队列的任务类型和资源模型。
