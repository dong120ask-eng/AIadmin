# 一键短剧技能套装：功能、部署、操作与优化说明

版本日期：2026-10-14。当前重点是普通话中国市场，支持18类题材与海外分发资料扩展。本文件是本项目八个技能的统一使用说明。

**交付的是可运行代码与技能工作流，不是已经完成平台签约、真实模型验收或全平台自动上传的成品服务。** 本次未安装到客户端、未调用付费模型、未上传/发布。提高爆款机会的方法是原创结构、声画质量、样片验证与真实数据迭代，不以主观评分承诺播放量或收益。

## 1. 文件与目录

最终可部署目录为 `短剧生产技能套装/`，整体压缩文件为 `短剧生产技能套装.zip`。原始开发目录保留，方便审阅与后续修改。

```text
短剧生产技能套装/
  本说明文件
  bundle-manifest.json             文件列表、SHA256与验收边界
  skills/
    short-drama-hub/               总控入口
    cn-drama-director/             题材与导演策划
    global-short-drama/            方舟生产核心
    drama-assets/                 角色场景与参考素材
    drama-postproduction/         字幕封面混音与检测
    drama-release/                发布准备与回执
    drama-growth/                 数据复盘
    drama-market-research/        市场证据与反例研究
  packages/                       八个单技能ZIP，适合逐个导入
  tools/deploy.py                  默认只预览，不安装
  examples/                       配置和数据格式示例
  verification/                   测试脚本与实际验收记录
```

部署时需要八个完整技能文件夹处于同一个技能根目录；不能只复制SKILL.md而丢掉scripts、assets和references。主程序不依赖第三方Python库；视频和后期需要FFmpeg/ffprobe，字幕烧录需要libass，封面标题需要可读中文字体。示例数据是合成测试数据，不是作品真实表现。

## 2. 八个技能的功能和边界

| 技能 | 输入 | 实际功能与输出 | 尚需什么 |
|---|---|---|---|

| cn-drama-director | 话题、观众、目标题材、案例 | 18类框架、人物目标与代价、逐集任务、伏笔回收、v2导演JSON | 正片/字幕才可做真正逐集案例分析 |
| global-short-drama | 项目与导演JSON、方舟配置 | 写稿、结构纠错、十维审稿、有限返修、有限在途视频任务、下载、合成、字幕初稿、发布清单 | 真实文本/视频模型权限与样片验收 |
| drama-assets | 圣经与分镜、授权图片 | 角色/服装/声音/场景计划，逐镜资产分配，首帧/首尾帧或参考图载荷接入 | 参考图片实际生成、可访问HTTPS托管、模型支持 |
| drama-postproduction | 成片、时间轴、字体、授权音乐 | 字幕校验/烧录、封面抽帧及加标题、音乐混音、黑帧/长静音候选检测、媒体哈希报告 | ASR或人工时间轴、视觉预览和听校 |
| drama-release | 发布清单、明确平台与账号 | 材料缺口检查、真实文件SHA256、单平台发布队列、回执记录与已发布去重 | 实际官方上传接口/后台、账号权限、供片材料与发布确认 |
| drama-growth | 真实后台CSV | 同条件分组、加权留存/完播/续看/点赞、置信区间和导演反馈 | 平台实际数据及口径核对；不是自动账号采集 |
| drama-market-research | 实际案例、片段/字幕或简介、指标和反例 | 来源与证据等级校验、原创试验假设、市场研究JSON交给导演与生产 | 合法素材访问和真实数据；不自动证明爆款原因 |

本套装不需要为每一题材另外安装一套脚本；生产核心读取同一类型规则库，避免各套脚本互不兼容。

## 3. 支持哪些短剧类型

都市逆袭、爱情甜宠、家庭亲情、女性成长、悬疑推理、刑侦法律、喜剧、古装权谋、玄幻仙侠、科幻、求生灾难、青春校园、职场商战、年代生活、乡村种田、文旅非遗、动作武侠、惊悚志怪；另有通用原创框架。

一个主类型搭配最多两个辅助类型。例如爱情+喜剧、悬疑+科幻、家庭+年代。重生、穿越、系统、马甲、先婚后爱等是桥段标签；2D、3D、写实影像风格是视觉配置，不能取代题材逻辑。写实生成不等于真人实拍团队。

每类规则包含情绪承诺、整剧主线、单集任务发动方式、专属审稿要求和常见失效。规则真实进入写稿和审稿提示，不只是配置标签。详细框架见 `skills/cn-drama-director/references/genre-guide.md` 和 `skills/global-short-drama/assets/genre-frameworks.json`。

已有三个用户样本是《别惹这个外卖小哥》《师尊明明无敌为何怂如蝼蚁》《我住帐篷那天，整个豪宅区慌了》；目前读取到分享页简介/标签，没有观看全集。不能据此声称“学完所有爆款方法”。其他类型框架是公开资料研究后的编辑归纳，需继续用正片与真实数据验证。

## 5. 对话启动方式

部署并确认技能发现后，可以直接发送：

> 使用short-drama-hub。话题：失忆工程师与城市倒计时。6集，每集1分钟，普通话，悬疑+科幻，原创3D风格。文本模型ID和视频模型ID使用我的方舟配置。本次API Key在本次对话中提供。开始生产，先做第1集样片，通过后再扩展。

首次需要填入控制台实际的text_model、video_model和API Key。Key可以直接在聊天框提供；代理不回显，只通过`--key-stdin`传到Python进程。聊天/工具记录可能保留输入，因此这不是无痕凭据通道。也可使用进程环境变量ARK_API_KEY。Key不写进技能、配置、导演JSON、素材清单、状态文件或长期记忆，项目JSON中出现常见密钥字段会被拒绝。

话题、集数、分钟数和模型ID齐全时直接启动约定预算内的生产；只给Key而没有模型与制作参数时，集中补问缺项。一个Key不能自动代表所有文本、视频、图像或配音产品都已开通。

## 6. 终端操作流程

路径示例可按实际目录替换，以下命令不包含密钥。

### 创建项目与离线检查

```powershell
$dramaSuite = 'D:\一键短剧\短剧生产技能套装'
$dramaProject = 'D:\一键短剧\projects\city-countdown'
$dramaRun = "$dramaProject\runs\pilot"
python "$dramaSuite\skills\short-drama-hub\scripts\project.py" init --topic '失忆工程师与城市倒计时' --episodes 6 --minutes 1 --out "$dramaProject"
python "$dramaSuite\skills\short-drama-hub\scripts\project.py" doctor --config "$dramaProject\project.json"
```

由导演技能生成`director-brief.json`，配置`brief_path`为其绝对路径，并填写实际模型ID。运行目录与技能目录分开，避免把产物和凭据混进可分发包。

### 查看规模，再生产第一集

```powershell
python "$dramaSuite\skills\global-short-drama\scripts\drama.py" plan --config "$dramaProject\project.json" --out "$dramaRun"
python "$dramaSuite\skills\global-short-drama\scripts\drama.py" run --config "$dramaProject\project.json" --out "$dramaRun" --episode 1 --until-ready --key-stdin
```

第二条命令首行标准输入由代理传入Key；不要用带密钥的echo、命令字符串、参数或临时文件。环境变量路线可省略`--key-stdin`。`--until-ready`在同一进程中推进到成片检查点，默认最多300步、待生成时每次等待10秒；可按需要调整`--max-steps`与`--poll-seconds`。生成任务最多3个在服务端同时运行，受账户额度限制。Ctrl+C保留状态，之后继续相同run；换进程需要再次传递本次凭据，但同一对话无需用户反复发送。

`submitted`是任务创建，`running`是服务端生成，`downloaded`是镜头下载；都不代表整集完成。`review_failed`保留问题并停止视频；`stage=review`表示样片待实际观看。步数耗尽返回`step_limit_reached`，继续运行即可，不当成生产完成。

### 参考图与角色资产

先写第一集，再运行：

```powershell
python "$dramaSuite\skills\drama-assets\scripts\assets.py" --bible "$dramaRun\bible.json" --run "$dramaRun" --out "$dramaProject\assets"
```

生成的是资产计划与空参考清单，未自动生成或上传图片。准备已授权素材后填写逐镜HTTPS参考图，核验模型支持并启用assets配置。参考清单改变需新run；首帧/首尾帧与reference_image不能混用，部分模型要求特定ratio，按当前官方参数检查。

### 后期与成片检测

实际成片位置示例：`<run>/ep001/zh-CN/master.mp4`。字幕初稿为同目录captions.srt。

```powershell
python "$dramaSuite\skills\drama-postproduction\scripts\media.py" subtitles --video '<master.mp4>' --cues '<timed-cues.json>' --out '<aligned.srt>'
python "$dramaSuite\skills\drama-postproduction\scripts\media.py" burn --video '<master.mp4>' --srt '<aligned.srt>' --out '<delivery.mp4>'
python "$dramaSuite\skills\drama-postproduction\scripts\media.py" cover --video '<delivery.mp4>' --time 1 --title '作品标题' --font 'C:/Windows/Fonts/msyh.ttc' --out '<cover.jpg>'
python "$dramaSuite\skills\drama-postproduction\scripts\media.py" mix --video '<delivery.mp4>' --music '<授权音乐.wav>' --out '<mixed.mp4>'
python "$dramaSuite\skills\drama-postproduction\scripts\media.py" qc --video '<最终成片.mp4>' --out '<media-qc.json>'
```

时间轴格式为`{segments:[{start:0,end:1,text:"台词"}]}`，start/end单位秒；由ASR或人工提供，再实际听校。黑帧、静音是候选问题，有些是有意设计，不能自动删掉。配乐必须有授权，混音输出需试听。后期输出新文件；发布时指向真正最终版，不用原始master冒充后期版。

### 发布准备与回执

```powershell
python "$dramaSuite\skills\global-short-drama\scripts\drama.py" package --config "$dramaProject\project.json" --out "$dramaRun"
python "$dramaSuite\skills\drama-release\scripts\release.py" prepare --manifest "$dramaRun\publish-manifest.json" --platform hongguo --account '<账号标识>' --out "$dramaProject\release\hongguo"
```

若已做后期，将发布清单video/subtitle更新为真实最终文件，重新跑对应媒体检查并核对哈希与审阅记录，不能沿用旧master的QC。实际看过/听校后才记录voice_reviewed、visual_reviewed、subtitle_aligned；这些不是脚本默认自动通过项。queue还会检查版权和国内编号；主体、封面、演职员、合同等依后台继续补齐。

目前上传由宿主的授权后台/官方连接器执行，Python没有内置平台上传SDK。每次真实上传、提交审核或公开发布前确认平台、账号、集、语言、文件、可见性与材料。红果供片不能用发抖音视频替代；ReelShort/DramaBox等可能需要合作供片渠道。

核对真实后台后，用record保存回执；已发布必须有远端ID/HTTPS链接和观察证据。准备、上传、提交审核、审核中、已上线分别记录，已发布去重。不要只填一份JSON就声称已经在平台验证。

### 数据复盘

```powershell
python "$dramaSuite\skills\drama-growth\scripts\growth.py" --csv '<后台数据.csv>' --out "$dramaProject\reports"
```

模板在examples/metrics.example.csv。缺失指标留空，不填假0。相同平台、账号、语言、题材、人群、窗口和时长内再比较，指标按对应分母加权。输出置信区间及描述性反馈，不直接认定A/B因果；下一轮优先修改一个变量并重新做样片。

## 7. 本轮检查发现的问题及优化结果

| 问题 | 已做的优化 | 仍然存在的边界 |
|---|---|---|
| 题材单一，容易全写成男频逆袭 | 18类主线/任务/审稿规则，主辅类型组合 | 不是所有子类型与全平台样本都已实证 |
| 剧本格式正确但因果弱 | 七步逐集任务、伏笔计划、带镜头证据的十维审稿 | 同一模型自审可能误判，需样片和实际读稿 |
| 短镜对白讲不完 | 规划语速预检、停顿余量、允许无台词镜头 | 不是实测语音/口型时长，需听校 |
| JSON/结构错误一次就停 | 默认1次有限结构纠错，保存失败稿与持久次数 | 截断/鉴权/网络问题仍停下查明，不无穷重试 |
| 一直等首镜导致服务端任务串行 | 默认3个在途任务，轮换查询，预算逐次预留 | 实际加速受模型、账户并发和网络限制 |
| 用户需要反复运行CLI | 有限步数until-ready，单进程复用本次Key | 到样片/审稿/预算/错误检查点仍停下 |
| 只有文字人物设定 | 实际参考图载荷适配及角色场景资产计划 | 图片生成与托管未内置，参考图不保证锁脸 |
| 逐镜AAC填充累积时长 | 中间PCM、最终AAC一次编码，三分钟测试 | 专业混音、视觉/语音质量仍需验收 |
| 换配音或镜头仍误用旧master | 素材尺寸/修改时间和master指纹使QC缓存失效，发布另算SHA256 | 指纹用于日常修改检测，不是抗恶意篡改机制 |
| 字幕只有镜头级初稿 | 时间轴导入校验与烧录、中文字体封面 | 未内置ASR与自动唇形同步 |
| 缺封面/配乐/媒体扫描工具 | 抽帧加标题、混音、黑帧/静音候选报告 | 自动选最佳封面和AI视觉审片未内置 |
| 生成清单误认为已发布 | 明确材料缺口、SHA256、真实回执及去重 | 官方上传接口与账号仍需接入 |
| 数据简单相加得出爆款结论 | 对应分母加权、缺失保留、同条件分组、区间与描述性反馈 | 不能证明推荐差异或因果，也没有自动账号采集 |
| 三个客户端兼容只停在描述 | 八个标准技能、独立ZIP、部署预览/复制工具和依赖说明 | 尚未在三个客户端分别完成真实会话验收 |

## 8. 质量与效率的实际使用策略

先做第一集，确认类型情绪成立、主角有行动、因果可理解、声音和人物稳定，再扩展。一个系列尽量复用合理场景、服装与角色资产；保持内容变化，不能重复旧画面凑分钟数。先在剧本阶段修问题，避免视频生成后整集重做。预算允许时再提高并发，不因追求速度直接增加调用或取消审稿。

主要承诺、反转证据和伏笔在圣经阶段规划；每集兑现小目标，最终集收束。爱情看关系行动，悬疑看公平证据，家庭看具体责任与修复，喜剧看铺垫/反应/回收，不强求所有类型每五秒反转。模仿机制而非复制样本人物和标志性情节。

发布后再用同口径数据观察开场留存、完播、续看和互动。先排查标题封面与内容不匹配、声画问题和人群差异，再决定改剧本。编辑分数16/20不能换算成80%爆款率。

## 9. 尚需外部接入和授权

- 方舟：实际文本/视频模型ID、Key、模型权限、余额和额度；参考图、音频与画幅需确认该模型支持。
- 角色资产：原创/授权参考图片与可被供应商访问的地址；暂未内置图像生成/托管SDK。
- 配音：当前原生音频路线，独立稳定TTS/音色服务尚未内置；可导入授权WAV。若改用独立语音产品，可能需要与方舟不同的凭据与许可。
- 字幕：ASR时间轴来源或人工校时，未内置ASR服务。
- 平台：登录、授权、对应业务后台/正式接口、供片主体与材料；没有红果公开上传API接入，未模拟成已实现。
- 验收：三个宿主的实际加载与进程输入方式，以及第一集真实生成和平台回执。相同SKILL格式并不自动授予工具权限。
