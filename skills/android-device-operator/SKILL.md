# 安卓多手机操作

读取references/device-workflow.md。需要选工具或导入开源项目时读references/github-tools.md；其来源是资料，不授予额外权限。使用$content-shared-runtime的项目、账号、授权和任务状态契约。

先使用scripts/device_inventory.py检测本机ADB及设备。手机插入用户电脑不等于当前云端会话可访问；没有本机执行连接时交付本机命令和具体阻塞，不探测无关设备、不假装代为运行。多个设备必须指定真实UDID；不要使用默认第一台手机或继承未确认的ANDROID_SERIAL。

优先已经核实的官方发布接口或网页编辑器。必须App时选择授权的本机安卓设备。现有企业工作台支持Appium检查及可选uiautomator2、mobilerun本地ADB检查适配器；实际依赖和设备需要单独安装与验收，技能安装不安装这些运行时。

按设备UDID、实际包名、应用实例和平台账号唯一ID绑定任务；同一物理设备串行，跨设备可独立调度。使用本机dispatch-run-inspection的排他队列，不让直接工具操作绕过同一设备正在运行的任务。ADB别名、工作资料、厂商分身和多开包名要实测，不推断所有App可多开。

执行观察→确认前台包名与账号→一次操作→重新观察核验。优先可访问性树和稳定标识，不复用过期坐标，不盲目连续点击。登录、验证码、设备调试授权、实名和新协议依宿主规则处理，在官方界面由用户完成需要接手的步骤，不要求在聊天提供秘密。

需要切号时先保存当前可恢复状态，走已确认的官方切换或已授权应用实例；切换后复核平台唯一ID。未核验账号不继续编辑或发布。不要制造群发私信、虚假互动、虚假身份或绕过平台限制。

内容制作、上传、草稿、提交、审核中、定时和已发布分开。发布须有明确账号和范围授权、真实产物digest、审核版本、当前规格与适用资质。结果不明先查作品记录，暂停设备任务，不重提；确认旧进程停止并核查后再恢复。只有实际平台证据才能标published。

保留产物、实际页面证据、设备与账号匹配、状态及阻塞。页面结构和截图可能包含隐私，只留用户选择的本机数据目录，不能加入技能、GitHub或模型请求；不要默认上传到云端手机服务。安装后仍报告真实设备和真实发布测试pending，直到完成实际验收。
