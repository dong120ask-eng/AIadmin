# 参考视频改编成自有产品视频：员工执行手册

版本：1.0.0｜核查日期：2026-10-15｜适用：人物、产品、声音需要替换，保留参考作品的结构与节奏，制作新的短视频。

## 先看这张任务卡

**推荐主路径：Codex 或 WorkBuddy 统筹 → 即梦制作关键帧与短片段 → 自己录音或剪映配音 → 剪映组装 → 人工质检。**

豆包可以承担文案、提示词和账号实际支持的视频生成；即创作为营销成片的另一条路线。第一次执行只选一条主路线，避免同时购买多个软件后反复搬素材。

本文件交付的是制作方法、指令和验收标准；配套技能包提供流程编排，不自带视频模型、会员、账号、商业素材授权或已经连通的软件执行器。当前没有收到实际参考视频、产品照片、人物照片，因此未制作样片、未验证真人一致性与实际成片效果。

### 员工今天先做什么

1. 收齐参考视频、产品实拍与说明资料、人物及声音使用授权。
2. 按下面的目录归档，填任务卡；不足的项目标“待补”。
3. 用“指令 1”拆片，输出带时间码的镜头表。
4. 重写自己的脚本，挑人物、产品、动作三类镜头做约 10 秒样片。
5. 样片合格再做整条；口型工具不可用时，采用旁白加产品镜头。
6. 交付 MP4、脚本、字幕、剪辑交接表和质检记录。发布须有具体账号与范围授权。

## 一、先把几件事说清楚

### 1. 参考爆款与照搬成片不同

可以学习“问题开场—展示产品—演示—收尾”的结构、镜头长度与情绪变化。默认重新写台词、生成或拍摄自己的素材；不把别人整段画面、原声音、字幕设计、音乐和独特剧情直接搬来改个脸就对外使用。若有改编授权，记录允许使用的素材、商业用途、平台和期限。

有视频不等于视频已经验证为爆款。没有曝光、互动、日期等证据时，任务中称“参考视频”。不得承诺换脸、换货后仍会获得同样流量或成交。

### 2. “卖点一样”不证明产品相同

品牌名、商品名、通用名、型号分别登记。特别是通用名不同，不能默认配方、用途、适用人群、使用方法或功效相同。用自己产品的标签、说明书与证据重写卖点；证据不清的句子删除或交负责人核实。涉及药品、医疗、保健等产品时，另行核验适用规则与可用表述，本手册不替代专项审核。

### 3. 换脸、换音色、对口型是三件事

| 目标 | 做法 | 验收重点 |
| --- | --- | --- |
| 人物换成自己的形象 | 授权人物参考图，制作新关键帧和新片段 | 每个镜头像同一个人 |
| 换声音、台词不变 | 重新录制或使用有权使用的音色，匹配节奏 | 音节、停顿与画面是否同步 |
| 台词也变 | 先定新配音，再用实际支持的口型功能，或重新拍摄 | 口型、表情、头部动作 |
| 产品换成自家包装 | 优先实拍；简单静态展示可合成或生成 | 品牌、形状、文字、规格准确 |
| 复杂拿取、拆包、涂抹 | 优先用自有实拍替代 | 手、物体、遮挡与动作符合实际 |

使用本人或明确授权的形象和声音。不得用他人面孔、克隆声音制造虚假代言、购买反馈或真实事件证据。不要绕过平台对真人照片、音色或人脸的限制；被拒绝时改用授权数字人、旁白或实拍。

| 材料 | 建议准备 | 合格条件 |

## 四、一步一步执行：直接复制的 AI 指令

### 第 1 步：素材盘点与能力检查

员工：把任务卡、参考文件、产品资料给 Codex 或 WorkBuddy；豆包需要逐次上传它能读取的材料。

```text
你是本项目的视频制作统筹。请先读取我的任务卡与现有素材。
逐项列出：已收到的文件、可读取情况、缺失材料、待核实卖点。
区分品牌名、商品名、通用名、型号，不因“卖点相同”判定产品相同。
检查你实际拥有的文件、视频读取、生图、生视频、配音、口型、剪辑工具。
输出能力表，使用“已验证可用 / 未接通 / 需员工操作”状态。
不要假装已观看打不开的视频；无法读取时给我提取关键帧和台词的办法。
可独立完成的整理先继续。只对会影响制作的缺项提问。
默认先做约10秒样片；不自动购买服务，不发布，不无限重试。
```

验收：素材索引和缺项清单齐全。AI 如果只回复“可以做”，要求它产出表格与文件。

### 第 2 步：拆解参考视频

员工：能上传视频就上传；不能读取的，使用剪映逐段查看，在每个明显切镜处截关键帧，并手动校对转写。只给截图就只能分析构图，不能推断未看到的动作和准确台词。

```text
分析我提供的参考视频，只根据实际可见可听的信息填写。
输出镜头表：镜头编号、开始/结束时间码、时长、叙事作用、景别、
机位/运镜、人物、产品、动作、台词/字幕、音效、转场、可迁移结构、
必须重做的部分、识别置信度。
原台词只作内部核对，不当成新脚本直接交付；无需逐字抄写整条。
没有真实播放与互动数据时，不把它认定为爆款。
分清观察与推测，未知项写未识别。统计总时长并核对镜头时间连续性。
最后挑三个代表镜头：人物、产品、人物与产品互动，组成约10秒样片。
```

交付：`参考镜头表.csv` 或 Markdown 表。时间码用 `00:00.000`；镜头衔接无遗漏、重复计时。

### 第 3 步：原创改编脚本

```text
根据参考镜头表和我的产品证据，写一条新的产品短视频脚本。
保留可迁移的节奏、叙事功能和情绪变化；改写具体台词、情境与表达，
使用自己的角色、场景与素材。未获授权不复制独特剧情或原片画面。
每句产品主张附证据文件/页码；缺证据就删掉或列为待核实。
不要制造专家背书、购买评价、销量、疗效或虚构对比实验。
输出A版（接近参考节奏）与B版（改变开场或视角），并说明镜头难度。
每版都给：旁白、人物口播、屏幕字幕、画面动作、目标时长。
明确每镜采用实拍、图生视频、静态合成或数字人口播的理由。
同一产品版本、人物造型、场景光线保持一致。
```

验收：负责人选一版。以实际配音计时；不要只凭字数判定能在固定秒数内说完。没有回复时可继续制作两版文本，付费生成遵循已给预算。

### 第 4 步：锁定人物和产品

员工：先挑同一个人的合格照片，产品选当前实际销售版本。生成一个人物设定卡、一张产品核对卡，不把人物图当成产品外观证据。

```text
建立人物C01与产品P01设定。
C01记录：参考照片名、面部可见特征、发型、服装、年龄外观、声音风格。
P01记录：产品证据图、包装形状、主色、品牌文字、规格、手持比例、开合方式。
标出不能靠生成模型重画的部分，例如商标、中文包装字、规格数字。
输出所有镜头共用的锁定描述，并按镜头关联参考文件。
如果当前工具不支持多参考或真人输入，给出静态合成、旁白、实拍替代方案。
不要承诺输入几张照片就能稳定保持所有角度的人脸和产品文字。
```

### 第 5 步：制作关键帧

员工：到即梦的图片创作或实际可用的参考图入口，上传对应图片。涉及精确品牌文字，优先用产品实拍抠图合成到画面；合成后检查透视、阴影、遮挡。包装不能准确就换实拍，不因整体“看着不错”放行。

通用关键帧指令：

```text
制作S01的单镜头首帧，目标为竖屏9:16的产品短视频。
人物：参考C01的人物照片，保持脸部特征、发型与服装一致。
产品：采用P01已确认的实拍外观，真实大小；包装内容以实拍为准。
场景：明亮的居家桌面，柔和侧光，背景简单。
构图：中近景，人物在画面偏左，产品展示区留在中下部。
动作状态：人物手放桌上，产品直立桌面，尚未拿起。
风格：自然摄影质感，肤色真实，避免过度磨皮。
不要生成字幕、额外Logo或其他品牌；避免多余手指、变形产品、漂浮物体。
如果不能准确保持商标和文字，保留干净展示区供后期合成实拍，不伪造文字。
```

上述“不要”是语义约束，不代表每个平台都有独立负向提示词字段。每镜头先选一张合格图，再进入视频生成。

### 第 6 步：关键帧生成视频

员工：进入即梦视频创作，优先用已合格首帧。账号有多参考、首尾帧等功能时再使用；没有就逐镜头制作。按界面支持的时长生成，剪辑时裁出需要的部分，不假设能精确生成任意 3 秒。

```text
基于S01合格首帧制作一个短片段，使用当前账号支持的最接近目标时长。
镜头固定或轻微缓慢推近，人物保持C01的脸、服装与发型。
动作只有一个：人物抬眼看向镜头并自然微笑，双手保持原位。
产品P01始终直立桌面，不旋转、不变形、不改变包装内容。
保持原场景、光线和构图；动作幅度小，前后连续。
本镜采用旁白，不要求人物开口讲话；不生成字幕与额外品牌。
重点避免脸变、手变、产品文字游移与突然切镜。
```

人物拿取产品的镜头另写指令，不把拿起、拆包、涂抹、展示都塞进一个片段。生成两次仍有明显变形，就降低动作复杂度或换实拍，不无限堆次数。

逐镜头模板：

```text
镜头编号：{Sxx}
输入文件：{首帧、人物参考、产品参考的准确文件名}
画幅与目标可用时长：{比例、秒数}
主体与外观锁定：{C01、P01}
开始状态：{位置、手势、产品朝向}
唯一主要动作：{一个可观察动作}
结束状态：{用于接下个镜头}
相机：{固定/轻推/其他单一运镜}
光线和场景：{与上一镜一致的要素}
音频策略：{旁白/原生音频/后续口型，不做无依据保证}
禁止变化：{脸、衣服、Logo、形状、数量等}
```

### 第 7 步：配音与口型

推荐先完成旁白版，人物露面的片段采用自然不说话的动作。如果必须人物说台词：先录好声音，再使用账号实际支持并允许该人物输入的口型或数字人功能；没有该能力就录真人，不把普通视频生成当成精确对口型工具。

配音文案指令：

```text
把已确认脚本整理成可录音稿，保留事实内容，按镜头分句。
标注停顿、重音、情绪和产品专有名词读音。
以自然中文交流语气，避免喊叫、机械推销和没有证据的承诺。
每句标目标时间窗；录制后以实际音频时长回填，过长则先精简台词。
声音使用本人录音或许可范围内的平台音色，不模仿参考视频里的真人声音。
输出纯净录音稿与“镜头—音频文件—入点—出点”表。
```

口型交接指令：

```text
先核实当前工具是否支持该人物、该视频、音频格式、时长与语言。
使用最终确认的音频版本，不在对口型后再擅自改词。
逐镜头制作并检查张口、闭口、停顿、转头与脸部边缘。
如需调整同步，优先移动整段音频、按句拆分或重生成，不大幅拉伸声音。
无法可靠对齐则输出失败镜头与原因，改用旁白配产品展示或真人补拍。
没有真实输出文件，不标记口型制作成功。
```

验收：耳听音节与眼看嘴形，重点看闭口音、句末和静音时段；不凭自动评分一项放行。

### 第 8 步：剪映组装、字幕、音乐

员工：新建项目，设置目标比例，导入合格镜头与最终配音，按交接表排时间线。逐句识别/输入字幕并人工校对，尤其产品名、规格、数字和承诺语。音乐来自有权商用的来源，不从参考视频截取后直接复用。

```text
根据已确认脚本和合格素材，生成剪辑交接表。
字段：镜头ID、素材文件名与版本、素材入出点、时间线入出点、
配音文件与入点、字幕原文及起止、转场、音乐/音效、画面备注。
确保各段时长、旁白和总时长一致；缺素材的镜头标待补，不引用不存在的文件。
给剪映操作员逐步说明：导入、排时间线、配音、字幕、音乐、导出。
只输出实际能生成的交接文件，不把CSV或伪JSON称为可导入剪映工程。
如果没有剪映控制工具，不声称已经创建工程或导出视频。
```

常用工作目标：竖屏 1080×1920、MP4/H.264、AAC、25 或 30 fps（与主要素材及交付要求匹配）。这些是内部建议，不是所有平台的强制规则；发布前按目的平台当日要求确认。避免把低清片段放大后标成“高清原生”。

字幕距边缘保留空间，用目标平台预览检查头像、标题、商品卡和互动区是否遮挡；不要把固定像素安全区当作全平台标准。

### 第 9 步：质检与交付

```text
请对实际成片及项目文件做质检。先列出实际能读取的文件与检查方式。
逐项检查：人物一致、产品外形与文字、手部互动、动作物理合理、
配音口型、字幕错字、音频爆音与断点、镜头衔接、素材授权、
卖点证据、AI标识适用要求、文件能否正常播放。
每个问题给出时间码、严重度、证据、修改动作与复检条件。
影响产品身份、虚假主张、未获授权或无法播放的问题阻止交付。
不能看视频或听音频的项目标“未检”，不能输出全部通过。
最终给出“可交付 / 需返工 / 信息不足”，并附实际产物路径。
```

交付前操作员全屏正常速度看一遍、静音看一遍、只听声音一遍；再检查首帧、尾帧、切镜附近及产品特写。短样片先全程检查，长片不能只看封面。

## 五、10 秒试做示例：只示范结构，不预设产品功效

这是虚构的“桌面收纳盒”流程示例，不代表已收到该产品，不承诺适用于其他品类。

| 镜头 | 时间线 | 画面 | 配音示意 | 推荐素材 |
| --- | --- | --- | --- | --- |
| S01 | 0–3 秒 | 授权人物面对略显凌乱的桌面 | 桌上这些小东西，总找不到？ | 人物参考图生成或自有实拍 |
| S02 | 3–7 秒 | 自家收纳盒的开合与物品放入 | 给它们安排一个固定位置。 | 产品与动作实拍，文字清楚 |
| S03 | 7–10 秒 | 整理后的桌面和产品 | 先看看尺寸，适不适合你的桌面。 | 产品实拍，原创排版 |

样片要同时检验脸、包装和动作；只做一个漂亮空镜不能证明整条可行。实际配音时长与生成片段可能不同，调整裁剪与台词后再定稿。

### 样片验收卡

- 人物在所有片段中可识别为同一人，且授权可追溯。
- 产品与当前销售包装一致；品牌、规格、数量不变化。
- 没有手穿物体、错误开盖、用法不符或凭空增减物体。
- 配音自然、字幕正确；口播镜头的嘴形与语音匹配。
- 每个卖点有依据，无照搬原产品主张。
- 试生成次数、实际扣费和返工原因已登记。

有一项关键问题不通过，就只返工相关镜头；产品文字或互动连续失败时，直接改为实拍。

## 六、即创替代路线

1. 登录即创官方入口，记录账号实际可见的功能与输入条件。
2. 如果看到脚本或成片入口，先投入自有商品资料与授权素材；没有对应入口，记录“当前账号未提供”，继续走即梦加剪映路线。
3. 粘贴下面的创作任务；若界面只接受分栏表单，将内容拆入对应字段。
4. 先制作短样片，检查人物、产品、配音和字幕；不把平台成片直接当成质检通过。
5. 导出可取得的文件，去剪映补实拍、改错字与整理节奏。

```text
我要为{自家品牌/产品/型号}制作一条{时长}{比例}营销短视频。
受众：{具体人群}。场景：{实际使用场景}。
已确认卖点与证据：{逐项填写}。
可用素材：{自有照片、实拍视频、许可音色或数字人}。
结构参考：问题开场—产品展示—真实使用动作—自然收尾。
请用新的台词与画面表达，不复用参考视频的完整文案、音乐和人物声音。
人物只能使用已授权的素材或可用数字人；不虚构买家体验或代言。
包装、Logo与规格必须正确，做不到的镜头改用产品实拍。
先生成脚本与镜头清单，再根据当前界面支持的功能制作样片。
```

这条路线便于尝试营销视频草稿；要精确控制某个运镜、角色或手部动作，仍需逐镜头生成或实拍。不能保证即创支持任意参考视频的一键人物和产品替换。

## 七、六个技能分别做什么

| 技能 | 输入 | 输出 |
| --- | --- | --- |
| video-reference-adapt | 任务卡、参考与产品证据 | 能力检查、镜头分析、原创脚本、制作计划 |
| video-shot-prompts | 已选脚本、人物和产品图片 | 设定卡、逐镜头关键帧与视频指令 |
| video-voice-sync | 最终台词、授权声音、视频 | 配音稿、口型路线和同步问题表 |
| video-edit-review | 合格素材与实际成片 | 剪辑交接、质检与返工列表 |
| video-jimeng-bridge | 分镜和参考图 | 即梦操作交接、能力记录与下载核验 |
| video-jichuang-bridge | 产品证据、自有营销素材 | 即创创作交接与样片检查 |

六个技能共享相同的输入、状态与版本规则。主技能可以调度其他技能；宿主没有子技能调用能力时顺序执行对应指令即可。它们不需要同时启动多个智能体。

## 八、部署和调用

### Codex

将发行包的 `codex/skills/` 下面六个完整文件夹复制到项目的 `.agents/skills/`。不要只复制 SKILL.md，要保留 references 和 agents。重新开始会话，确认技能列表能发现它们。旧版客户端的发现路径可能不同，以实际客户端与官方文档为准。

也可在解压后的套件目录运行以下命令安装到指定项目（需要 Python 3；已有同名技能时会停止并保留原件）：

```powershell
python tools/install_codex.py --project "D:\视频改编\项目001"
```

发送：

```text
请使用 $video-reference-adapt。
本项目素材在{实际项目路径}。读取任务卡与产品证据，先建立素材索引，
拆解可读取的参考视频，重写原创脚本，并准备约10秒的代表样片方案。
先检查是否有真实可用的视频生成、配音、口型、剪辑工具。
已接通的步骤按现有授权执行；未接通的步骤输出可复制提示词和员工待办。
请保存每个阶段的文件和状态，不把写好提示词当成已生成成片。
```

验收：能读到六个技能，并先产生盘点与计划。六个技能已制作并通过结构检查。当前 Work 的个人技能同步返回 HTTP 422，尚不能确认在技能页可用；可使用发行包安装到 Codex 项目。这也不等于已经在 Windows 电脑安装。

### WorkBuddy

发行包 `workbuddy/` 下有六个独立 ZIP。按官方文档，从技能页“添加技能—上传技能”逐个导入，不要把整个总发行 ZIP 当成一个技能。启用后新建对话，引用实际可访问的素材目录。

发送：

```text
请调用“参考视频原创改编总控”技能（video-reference-adapt）。
素材目录是{路径}。先读任务卡并检查输入，再拆片、写新脚本，
准备人物和产品设定、逐镜头即梦/即创指令、配音稿、剪辑交接表。
先做约10秒样片方案。只有在工具真实可用且在已有授权范围内时才执行生成。
若不能控制软件，给员工逐步待办，说明需要上传什么、粘贴哪段、保存什么。
输出待补材料、阶段文件和真实状态，不把技能已启用当成外部软件已连通。
```

验收：导入成功后能触发、能读取 references、能输出文件。没有在用户 WorkBuddy 实机导入测试前，部署状态写“包已适配、实机待验收”。

### 豆包

使用发行包 `adapters/豆包启动指令.md`，粘贴启动指令，再按阶段上传材料。普通聊天不假设有本地目录权限或原生技能 ZIP 安装入口。若产品界面提供自定义助手/知识配置，可把规则放入对应配置，但需实际确认功能。

首轮只发任务卡与“指令 1”；随后逐镜头上传图片或在视频创作入口输入提示词。豆包客户端视频生成与火山引擎 API 是不同路径，分别确认权限、额度与限制。

### 即梦与即创

它们在本包中是被操作的制作工具，不假设能直接安装 SKILL.md。对应技能安装到 Codex 或 WorkBuddy，由助手生成表单内容与员工待办。需要自动操作时另接真实网页执行器、官方 CLI 或 API，按当前官方文档验证，不复制来源不明的安装命令。

## 九、失败处理、预算与工作分工

| 问题 | 优先修法 |
| --- | --- |
| 人脸不一致 | 固定参考图与服装，减少转头；换实拍或授权数字人 |
| 包装字错误 | 产品实拍替换；不要用文字提示反复碰运气 |
| 手拿产品不自然 | 先缩小动作，仍失败则补拍拿取镜头 |
| 对口型失败 | 按句拆分并使用定稿音频；改旁白或真人重拍 |
| 只有截图没有可读视频 | 产出静态构图分析；台词、运镜标未知 |
| 软件没有对应功能 | 记录能力缺口，改人工或替代路线 |
| 生成超时 | 先查原任务编号与状态，避免重复付费提交 |
| 片段有水印或标识 | 使用符合授权的导出；不抹除来源或 AI 标识 |
| 时长不够 | 简化脚本或补合法自有素材；不无限慢放制造卡顿 |

预算公式：本轮成本＝合格片段生成＋失败与重试＋配音/口型＋素材授权＋人工时间。会员和 API 分开计费，先核对实际页面，不在本手册写死价格。任务卡未给付费额度时，先完成免费可做的文本和整理，不自动购买或启动付费任务。

建议分工：负责人确认产品主张和目标；制作员拆片、生图、生视频；剪辑员处理声音与合片；复核员按时间码验收。一个人也可顺序执行，但交接文件仍需留下。

不承诺固定用时。先记录样片实际耗时、合格率和成本，再估算全片。所谓“全自动”至少需要素材输入、模型调用、任务恢复、下载、剪辑和核验全链路实测，只有一组提示词不能算全自动。

## 十、真实状态、自动化接入与交付

阶段状态使用：`waiting-input` 等素材、`planned` 已做方案、`waiting-operator` 待操作、`submitted` 有真实任务回执、`generated` 真实文件可读取、`reviewed` 已检查并记录结果、`delivered` 文件交付完成。单独记录 review_result 为 pass、fail 或 uninspected；reviewed 不代表通过。

后续接火山引擎 API，开发人员必须完成：核对当前官方接口与模型权限；通过环境变量/密钥管理保存凭据；按接口支持情况提交任务并保存回执；有界轮询与超时恢复；下载结果并确认真实媒体；登记扣费与输入版本；失败不能盲目重提；再连接剪辑和质检。不要假定某个 API 一定支持真人参考、对口型、产品替换或幂等参数。

本包未内置未经验证的 API 调用器，未安装或操作用户本机的软件，未进行实际视频生成或账号发布。

### 最终交付清单

- `成片_v01.mp4` 与可正常打开的预览。
- 最终原创脚本、分镜表、人物和产品设定卡。
- 配音文件、已校对字幕（SRT 或平台支持的格式）。
- 素材索引、提示词与生成任务记录、实际成本。
- 剪辑交接表；有真实剪映工程时另交工程及素材依赖。
- 逐镜头质检记录、待修问题、可使用素材的授权记录。

### 开源与部署状态

本套原创规则、模板与脚本采用 MIT 许可；不包含参考视频、人物照片、产品客户资料、商业模型权重或第三方软件。公开发布时只提交代码和空白模板，不提交客户素材、账号、密钥或授权证明原件。

本次读取到 AIadmin 仓库的可见性仍为 private。代码保存到仓库与对公众开源是两件事；只有仓库改为 public 并经验证后才能标记公开。当前连接器没有更改仓库可见性的工具，因此公开状态需要在 GitHub 仓库 Settings → General → Danger Zone → Change repository visibility 完成后核验。
