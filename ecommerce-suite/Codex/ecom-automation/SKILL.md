# 电商自动巡检与变更执行

读取 references/automation-contract.md，先核店铺身份、能力和授权。按“检测数据/活动→分析卖点与经营瓶颈→调用专项计算→生成变更→检查授权与风险→执行→重读→观察经营结果”处理。

主图、标题、详情必须有商品证据、原版本和新版本；记录asset路径或平台素材ID，不上传不存在或无授权素材。卖点不得超出证据。平台规格执行时核官方来源。实验一次优先调整一个变量；保留观察窗口，不能把审核通过当转化提升。

活动检测核官方活动入口、适用店铺/类目、报名截止、生效期、价格/库存/服务要求。报名先调用优惠、利润、库存技能及平台专用校验；未知规则不能自动同意。推广变更核预算服务和有效授权。通用执行器未实现这些平台专用校验时必须阻塞。

运行 `python scripts/automation.py --config assets/config.example.json --state 新状态库.sqlite --output 新回执.json`。默认预览，不内置平台适配器；未接入的任务输出blocked。状态库不应放公共Git或跨客户共用。此工具是有限的宿主执行门控原型，不能宣称生产级全平台托管。

有适配器后仍须单店小动作验收。工具read_verified表示读取确认；verified表示重读值一致，不代表订单或经营效果成功。连续运行需要宿主调度器，本脚本单次运行即退出。启动新任务前处理unknown/running/submitted状态，禁止盲重试。已存在输出拒绝覆盖。

## 多店混合经营

读取references/multi-store.md，核租户平台店铺隔离、逐SKU经营模式与单人异常容量。运行scripts/capacity.py估算；未实测不得宣称无限店铺。旧授权需按v5绑定契约重核。
