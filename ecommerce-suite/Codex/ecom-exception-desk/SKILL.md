# 单人多店异常待办

把异常按租户/平台/店铺/订单或SKU唯一定位，建事件ID、首发时间、证据、影响金额/订单、截止、状态、唯一负责人和升级负责人。重复提醒按同一根因聚合，不能删除各店明细或把跨主体事件混合授权处理。

P0关注安全、资金、错价超卖及正在扩大影响；P1关注时效将到、客户承诺与持续亏损；P2关注优化。优先级为项目约定，缺金额或规则标未知，不自动推定欺诈或恶意买家。通知渠道未接通只产通知草稿，禁止冒称已通知。

用ecom-automation/scripts/capacity.py估计日常人工+异常量×处理时间，设置每日人工分钟、积压阈值和接单上限。超负荷时建议减投/暂停扩店/增加承接人，在已有授权范围内执行；不能以“无限店铺”替代容量验收。

异常关闭需要根因、处理证据、客户/业务结果及复发检查；仅发通知不能关单。区分待处理、处理中、待外部、已修复、已验收。

先读references/execution.md，涉及平台政策核当前官方来源及适用类目。缺数据先完成独立工作并列最少补数项。已有有效授权内直接做，缺权限或工具先给可审阅操作包。结果区分已生成、已提交、平台存储值确认、审核通过、展示生效和真实业务结果。
